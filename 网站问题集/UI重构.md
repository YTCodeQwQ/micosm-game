# 重构排位页面 UI

请基于当前页面进行 UI 重构，**不要只做局部样式微调，需要调整整体布局结构**。

## 当前主要问题

1. 页面使用三栏等高布局，但三个区域内容量差异很大，导致大量无意义空白。
2. 中间「段位路线」和右侧「围棋榜」内容很少，却被强制撑满整个屏幕高度。
3. 左侧排位信息全部挤在顶部，下方又存在大片空白，页面视觉重心失衡。
4. 整体颜色过淡，背景、卡片、文字、边框对比度不足，视觉层级不明显。
5. 当前段位、赛季信息、玩家信息、排位入口彼此分散，没有形成完整的信息结构。

## 修改目标

将目前的：

`左侧排位 / 中间段位路线 / 右侧排行榜`

三栏布局，改成：

`左侧主内容区 70% + 右侧排行榜 30%`

### 左侧主内容区

按照从上到下的顺序组织：

1. 赛季信息
2. 赛季 Banner
3. 玩家信息
4. 当前段位
5. 段位积分 / 胜率 / 战绩等数据
6. 「开始围棋排位」主按钮
7. 段位路线

把目前分散的「排位信息」和「当前段位」整合成一个完整的排位信息模块。

「段位路线」不要再单独占一整列，直接放在左侧排位模块下面。

### 右侧

只保留「围棋榜 / 排行榜」。

排行榜宽度约占页面 25%～30%。

如果排行榜暂时没有数据，可以显示 Empty State，但不要因为内容少就把整个卡片强行撑满页面。

## 布局要求

- 删除当前三栏等宽/等高布局。
- 禁止使用为了撑满屏幕而设置的巨大 `min-height`、固定高度或者 `100vh` 卡片。
- 卡片高度必须根据内容自然撑开：`height: auto`。
- 页面可以自然向下滚动，不要求所有内容强行塞进一个首屏。
- 主内容区域明显比排行榜区域宽。
- 保持合理的卡片间距，大约 16～24px。
- 减少目前大面积没有任何内容的空白区域。
- 页面最大宽度可以继续保持居中，不需要铺满整个显示器。

建议布局：

```text
┌─────────────────────────────────────────────┐
│                  顶部导航                    │
├───────────────────────────────┬─────────────┤
│                               │             │
│       排位 / 赛季信息          │   围棋榜    │
│                               │             │
│  Banner                       │  排行玩家    │
│  玩家信息                     │             │
│  当前段位 + 数据               │             │
│  [ 开始围棋排位 ]              │             │
│                               │             │
├───────────────────────────────┤             │
│                               │             │
│          段位路线              │             │
│  尘星                         │             │
│  微光                         │             │
│  星轨                         │             │
│  月环                         │             │
│  ...                          │             │
│                               │             │
└───────────────────────────────┴─────────────┘
```

## 视觉调整

不要改变目前整体的浅色、二次元、简洁风格，但需要增强视觉层级。

具体调整：

- 页面主标题颜色加深。
- 正文文字不要全部使用非常浅的灰色。
- 次要说明文字可以继续弱化。
- 卡片与页面背景之间增加一点对比。
- 边框可以稍微明显一些，但不要变成深色粗边框。
- 当前段位、积分、赛季状态等核心信息需要更加突出。
- 「开始围棋排位」继续作为页面主要 CTA。
- 不要大量使用阴影，保持轻量、干净。
- 不要把所有元素都做成独立小卡片，避免 Card 套 Card。

## 段位路线

目前段位路线太像普通设置列表。

重新设计成更明确的「段位进阶路线」。

例如：

```text
尘星       当前段位
│
微光       100 - 199
│
星轨       200 - 299
│
月环       300 - 399
│
曜辰       400 - 499
│
星穹       500 - 599
│
天幕       600 - 699
│
无垠       700+
```

当前段位需要明显高亮。

可以使用：

- 连线
- 节点
- 段位图标
- 当前段位高亮背景

让用户能够一眼看出：

**我现在在哪个段位 → 下一个段位是什么 → 还需要多少分。**

## 排行榜

不要只在一个巨大空白区域中央放一个 Empty State。

有数据时显示实际排行榜，例如：

```text
1  用户A        1250
2  用户B        1180
3  用户C        1090
4  用户D        1030
5  用户E         980
```

没有数据时，卡片高度保持正常，例如 300～400px 左右，不要撑满整个页面。

## 响应式

桌面端：

- 左侧约 70%
- 右侧约 30%

较窄屏幕：

- 自动改成单列布局
- 排位内容在上
- 段位路线其次
- 排行榜最后

## 重要限制

不要：

- 重写业务逻辑
- 修改现有 API
- 修改排位算法
- 删除现有功能
- 随意更换现有二次元素材
- 把设计改成完全不同的风格

优先复用现有组件、数据和 CSS，只重构页面布局、信息层级和视觉表现。

完成之后请检查：

1. 首屏是否还存在大片无意义空白。
2. 是否仍有卡片被强制撑满整个页面。
3. 用户是否可以第一眼看到自己的当前段位。
4. 用户是否可以第一眼找到「开始排位」。
5. 是否能直观看懂下一段位以及所需积分。
6. 排行榜是否真正像一个侧边排行榜，而不是一整列空白区域。

核心目标：**提高页面信息密度、减少空白、增强视觉层级，让排位页面看起来像一个完整的游戏排位中心，而不是三个被强行拉高的后台管理面板。**
